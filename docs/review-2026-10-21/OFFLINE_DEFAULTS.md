# Rainier and Enchantments offline download defaults

The user selected **Mount Rainier via Emmons Glacier** and **Enchantments & Dragontail** as the default downloads. Both are checked in the new offline-download section of the desktop/headset-browser settings. This checkpoint implements user-started preparation, pinned storage and offline application startup. It does **not** claim that the complete multi-gigabyte packs have been acquired, that source-native repackaging is finished, or that a signed installed Quest app or native frame rate has been accepted.

## Download behavior

Choose **Estimate selected**, review the displayed capacity, then **Download selected**. The default inventory preserves full surrounding terrain and current public High satellite detail through Z19, with complete overview levels. It uses public USGS imagery and 3DEP elevation, not private Bing credentials. The existing online viewer, uploads, lighting, mesh sampling and CPU/GPU residency limits are retained. Unsupported styles/providers, Balanced or experimental grid options are not advertised as fully covered by these High satellite packs.

Plans are generated from the bundled GPX using the production coordinate, imagery-group and terrain-layout functions. Images share the original 1024-square raster among sixteen fine child crops. Both normal High base-grid variants are included, with duplicate requests removed and all required elevation-support windows combined. Existing overview margins and legacy local DEM request identities are retained; the unaccepted compact-request experiment is not enabled. No source request is made just by calculating the inventory.

The initial checkpoint required raw RGBA/F32 capacity plus 10%: approximately **18.3 GB Rainier / 27.8 GB Enchantments**. The follow-up corrects this excessive minimum-quota gate: those values remain explicitly labelled uncompressed planning budgets, while original encoded PNG/LERC bodies are stored. They differ from the earlier encoded planning ranges, which sampled compression and used a proposed compact terrain-baking inventory. Actual retained compressed bytes appear during download; no smaller guaranteed full-pack size is claimed.

Shared-origin quota/usage is rechecked before each new acquisition and before each actual encoded write, leaving 32 MiB working/metadata headroom plus a 10% allowance on the next body. This is a guard, not a quota reservation: concurrent browser writes can still cause IndexedDB to reject a write. Either failure pauses with only committed progress retained, without deleting other packs. A complete staged pack can still be verified and published when little space remains. Unknown/invalid capacity blocks new acquisition. Elevation (overview first, then local sources) is validated before the thousands of imagery exports, so DEM coverage problems are discovered earlier. Ordering changes do not change URLs, pack IDs, coverage, precision or existing resumable staging. Source-native archive preparation and accurate prebuilt encoded manifests remain important size/startup work.

One bounded acquisition/validation lane runs in the foreground. Play, XR entry and page exit pause it; a browser-wide Web Lock prevents competing download/removal operations. An interrupted tab is shown as resumable. Resume verifies retained source hashes and coverage, without downloading or rewriting valid bodies. Every PNG's declared size is checked before bitmap allocation, then dimensions/alpha coverage are checked. LERC is decoded in the terrain worker and requires all samples supporting the rendered footprint; no heights are invented. A missing/invalid source pauses rather than silently substituting coarse data into a supposedly complete pack.

## Storage, integrity and updates

`trekviewer-offline-packs-v1` has independent pack/asset stores. It is outside the temporary cache's 256 MiB cap, seven-day expiry, opt-out and clear action. Each body retains its source URL, aliases, byte size and SHA-256 after acquisition from an approved HTTPS source and coverage validation. This is local integrity, not an assertion that a publisher supplied a pre-existing authenticated content manifest. No imported arbitrary manifest is accepted in this checkpoint.

Staging is invisible to rendering. A pack becomes ready only after all required sources pass validation and the asset-count check and visibility transition commit atomically. Reads verify retained bytes before exposing them through the normal DEM/image loaders, including when temporary caching is disabled. Corrupt or undecodable data unpublishes the affected pack and removes the failed asset for repair. Explicit **Remove pack** runs under the same management lock. Pinned bodies are paged as individual encoded resources, not loaded as a complete archive into RAM.

Plan IDs bind the route revision and v1 provider/layout contract. GPX revision hashes normalize line endings so a Windows/Linux checkout change does not invalidate gigabytes of otherwise identical data. The built app carries the corresponding route hashes; mixed app/GPX revisions cannot start a download, and older ready packs are not presented or served as complete coverage for a new route revision. Old revisions remain on disk until explicitly removed. Future renderer/provider/layout changes must revise the plan contract. Portable archive import/export and an independent geographic source index remain follow-up work.

## Offline application shell

The build inventories the final integrity-stamped HTML, entry/imported chunks, terrain worker, LERC WASM and public GPX/regional DEM/icon/credit assets. `sw.js` installs every resource with a SHA-256 check before becoming active; a failed installation removes its incomplete new cache and retains the old version. Runtime requests use one coherent shell version. It never handles cross-origin/private map requests and does not replace missing JS/WASM with HTML.

Updates deliberately do not call `skipWaiting()` or `clients.claim()`: existing tabs and XR sessions keep their version until closed. Settings reports when reopening is needed for an update. Shell activation only removes older TrekViewer shell caches, not route-pack IndexedDB or unrelated caches. Browser persistence is requested when a download begins and its result is reported; browser quota/eviction and installed-runtime behavior still require Quest acceptance. Initial online provisioning is required. The existing APK wrapper alone is not changed into a self-contained first-launch-offline package.
