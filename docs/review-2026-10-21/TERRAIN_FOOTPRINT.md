# Validate the rendered DEM footprint before falling back

Stable tiled terrain previously acquired a square DEM whose half-width was the larger tile dimension plus 100 metres. This fetched unused height samples beyond every edge, especially for rectangular boundary tiles. It also rejected the complete raster if even one NoData sample occurred in that unused area. This is the still-applicable NoData finding from the supplied architecture review, with a bounded fix that preserves actual missing coverage.

## Accepted default and experimental request shape

The tiled streamer now supplies its exact geographic mesh bounds, converted through the same reference centre as its vertices. **The normal application retains its existing USGS export bounds, sample counts and cache identities.** Overview requests, legacy stations and Terrarium fallback also retain their request/coverage paths. Source selection, lossless compression, imagery, mesh dimensions, detail anchors, geometry/residency/concurrency limits and lighting are unchanged.

A separate developer-only experiment (`terrainSourceBounds=compact`) expands the exact tile footprint by a four-metre guard in EPSG:3857 and uses endpoint-inclusive dimensions. It meets the requested one-metre sample spacing within the existing 1024-side cap and reduces unused samples, but changes request identities. Its first full-tour loading result fails the useful-detail gate below. **It is not enabled by default or accepted as a loading improvement.**

The LERC worker counts coverage of the mesh's entire bilinear-support window, including an extra source sample around its bounds for Float32 coordinate roundoff. Every sample in that window must be valid. Missing values outside it remain NaN; missing values within it still reject the preferred raster and retain the existing fallback. There is no invented height or interpolation across missing survey coverage. Successfully decoded partial encoded bytes are reusable rather than treated as corrupt. Coverage backoff is specific to the required window; malformed data retains the existing corrupt-cache recovery and network backoff. The bounded decoded-grid cache keys footprint-validated data by the exact required bounds.

[USGS describes this service as multi-resolution 3DEP](https://elevation.nationalmap.gov/arcgis/rest/services/3DEPElevation/ImageServer); one-metre export spacing is not a universal one-metre native-survey claim. The [upstream LERC mask convention](https://github.com/Esri/lerc) distinguishes genuine valid pixels from NoData. The original failed Bing overview had complete coverage, so this correction alone does not explain or resolve its whole-model DEM feedback.

## Experimental request-size evidence

The [layout audit](terrain-footprint/layout-audit.json) checks **2,504,034 stored Float32 row/column positions** across all **11,158 tile layouts** of the eight bundled routes, using current High base-grid policy with constrained/desktop vertex caps. Every possible rendered coordinate combination has complete bilinear support within its guarded window. One export of each possible layout requests **6,598,921,044 pixels before / 3,653,541,964 after (44.63% fewer)**. This is a layout calculation, not an app-wide download or timing result; normal streaming loads a subset. The maximum new requested sample spacing across those layouts is below one metre. No coarse base mesh is made finer by this change.

Three [matched real Olympus export pairs](terrain-footprint/live-pairs.json) cover the beginning, midpoint and end tile meshes. LERC compression tolerance remains zero. Their encoded bodies total **10,967,442 bytes before / 7,007,618 after (36.11% fewer)**, with all **70,227 rendered vertex samples** valid in both versions. Narrower requests change the export-grid phase, so heights are not bitwise identical: maximum absolute difference is **0.164 m**, p95 at most **0.020 m**, RMS at most **0.010 m**. New sample spacing is approximately **0.9990–0.9999 m**, versus approximately **1.0001 m** before. These pairs do not establish a matched time-to-detail, native source-resolution or frame-rate improvement.

Reproduce the pure audit with `node --experimental-transform-types scripts/audit-terrain-footprints.mjs`; set `TREK_FOOTPRINT_NETWORK=1` for the paired public-source exports. This script retains URL-specific encoded files in the ignored review cache and never loads private provider configuration.
