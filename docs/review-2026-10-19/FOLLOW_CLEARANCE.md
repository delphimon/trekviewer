# Desktop flyover terrain clearance

The fixed desktop Follow route offset could leave the hiker hidden behind nearby terrain, including when the camera endpoint itself was above ground. A shaped ridge in the clean `b9e6993` production build reproduced this using the real base mesh, shared height data and production triangle sampler. After following settled, the sampled sightline clearance was **−0.209 desktop scene units**. [Baseline](follow-clearance/baseline.json), [obstructed view](follow-clearance/before.png).

The follower now samples the current rendered terrain at 16 stations between the hiker and intended camera, raises that camera as needed, smooths toward it, and checks the actual smoothed position with another 16 samples. Heights include the current vertical exaggeration and terrain group's world transform. The endpoint margin is 0.015 desktop scene units and tapers toward the hiker. Downward movement remains smooth when the obstruction clears; upward correction can be immediate to avoid staying inside terrain after scrubbing or a surface update. Pending orbit inertia is drained before follow starts.

In the same desktop and mobile fixture, the sampled sightline clearance becomes **+0.00537 scene units**. The hiker and route become visible over the ridge. [After](follow-clearance/after.png), [mobile](follow-clearance/mobile-after.png), [browser results](follow-clearance/browser.json).

Only active desktop Follow route performs these queries. Manual inspection remains free, and dragging, zooming, Fit terrain, route replacement, view changes and XR entry still release follow. The model and terrain geometry are not changed by the production follower. It replaces its terrain reference on route commit and releases it on teardown. XR tours continue to animate the hiker without steering the tracked camera or tabletop.

Validation includes six new regressions covering intervening ridges, endpoint clearance during scrubbing, streamed height/exaggeration changes, smooth descent, translated/rotated/scaled terrain, terrain replacement/teardown, unavailable heights and singular transforms. The full suite passes **642 tests (5 skipped)**, source/test typechecking and production build. Desktop 1440×1000 and mobile 390×844 browser checks also retain pause/scrub/timing controls, manual takeover, loop-landmark navigation, prefixed GPX import/error recovery, clear spatial control rows and zero page errors/overflow.

This is bounded sampled clearance, not continuous collision detection or a flight-path guarantee. Narrow obstacles between sample stations can be missed. The query count is fixed, while each surface query can inspect resident refinement chunks; native performance improvement is not claimed. Fixture terrain is deliberately synthetic, external data requests are blocked, and screenshots do not establish imagery fidelity. Existing SAX/LERC browser externalization and large-chunk build warnings remain.

Reproduce the historical obstruction using the browser driver with `TREK_FOLLOW_BASELINE=1` against a local build of `b9e6993`; omit that flag for the corrected client. The driver asserts the actual entry asset and exact build ID. The October 19 device check again found no headset; the [native tabletop protocol](HUD_STATUS.md#prepared-native-tabletop-baseline) remains open, and new 1:1 work remains deferred.
