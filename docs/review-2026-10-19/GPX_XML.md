# Shared GPX reader for diorama imports

The architecture review correctly identified different production and test parsers. Browser imports constructed a DOM, while Node tests used regexes requiring latitude before longitude and explicit closing point tags. That fallback also accepted malformed XML and could merge separate tracks/routes. Browser selectors did not consistently support prefixed GPX elements, and absent coordinate attributes could become zero.

`GPXXMLReader` now supplies the same raw data path in both environments using the synchronous, namespace-aware API from [sax-js](https://github.com/isaacs/sax-js). GPX validation, DEM normalization, route metrics and derived landmarks remain downstream. The reader supports the official GPX 1.0/1.1 namespaces and legacy unnamespaced files, arbitrary coordinate attribute order, self-closing points, XML entities/CDATA, and heart-rate/cadence extensions with arbitrary prefixes. Vendor elements cannot replace core elevation or track elements. Segment and track boundaries remain separate; routes are used only when no track points exist.

The existing 25 Mi-character string guard, 100,000 track/route-point limit and 1,000-waypoint limit remain. Point limits now count actual XML elements, including prefixed/self-closing tags. A 128-level nesting bound prevents excessive parser state. DOCTYPE/custom entity declarations are rejected; imports do not fetch external definitions. Missing, empty and partially numeric coordinates are invalid rather than invented locations. File-upload byte-size checks remain in the desktop UI.

## Evidence

- [Curated route comparison](gpx-xml/curated-routes.json): all eight bundled routes, totaling **27,772 points**, match the complete finalized output from `412c9b3` exactly, including coordinates, timestamps, elevation provenance, metrics, warnings and landmarks. Reproduce with `node docs/review-2026-10-19/gpx-xml-compare.mjs` on Node 24.
- Sixteen new XML regressions cover namespaces, reversed attributes, self-closing points/waypoints, entities/CDATA, extensions, track/route selection, missing coordinates, malformed roots/tags/entities, count/size/depth limits and independence from browser DOMParser. Existing count-limit tests now use valid XML so they exercise the actual element counters.
- **636 tests pass, 5 skipped**; source/test typechecks and production build pass. [Browser results](gpx-xml/browser.json) cover 1440×1000 desktop and 390×844 mobile. A prefixed two-segment import preserves all four points, encoded route/waypoint names and fitness values through the terrain worker. A subsequent malformed import leaves that same diorama committed and reports the import error. Tour/follow, loop-landmark navigation, clear HUD control rows and responsive layout continue to pass with zero page errors.

This is import correctness and architecture coverage. The reader remains synchronous and adds a locked runtime dependency; no native frame-rate or parsing-speed improvement is claimed. Vite externalizes the package's optional Node `stream` API, which the application does not call; the actual bundled browser and worker paths are exercised above. Existing LERC externalization and large-chunk warnings also remain. Browser fixtures deliberately block external terrain/imagery sources and do not establish source fidelity.

The October 19 device check still found no connected headset. Native anchored-tabletop tour acceptance and the measured terrain-performance baseline remain open under the [prepared protocol](HUD_STATUS.md#prepared-native-tabletop-baseline); new 1:1 work remains deferred.
