# Offline NAIP source recovery

Real Rainier acquisition exposed a genuine source-coverage failure, alongside repeated service timeouts. The offline inventory now includes the same GeoPlatform NAIP source already used by the online viewer. All current PNG alpha checks, lossless bytes, elevation validation, High coverage, zoom levels, terrain geometry and GPU budgets remain intact. Complete default packs, real offline full tours and native acceptance remain open; no headset was queried or launched.

## Observed failure and replacement

The v1 Rainier run stopped after 1,770 validated sources, approximately 1.33 GB of original data. All 523 elevation requests had passed production coverage validation. Source 1,771 (zero-based index 1770) is a 1024 × 1024 high-detail export: NAIP Plus contains four transparent pixels and USGS NAIP contains three. They lie around source pixel (418,419). Removing the request's `noData=0` override returns the same hashes/masks, so that proposed explanation does not resolve the gap. The checks correctly refuse to publish incomplete imagery.

The existing online provider's GeoPlatform request returns **zero transparent pixels** for this exact extent, dimensions and zoom. Its original PNG is **1,748,194 bytes**, SHA-256 `7e47e549a42a9031c1c88d9cf243efbdc927a9e8dcb5c7662091ba1b5b77edd7`. The [source comparison and production validation](naip-gap-recovery/source-gap.json) retain all three original request identities and hashes. Pixels are neither filled nor re-encoded. The full original alternative image is used with its actual source provenance, rather than replacing a few pixels locally or enlarging an overview tile.

The [GeoPlatform service metadata](https://imagery.geoplatform.gov/iipp/rest/services/NAIP/NAIP_plus/ImageServer) identifies USDA FPAC imagery served by USFS GTAC with DOI GeoPlatform/IIPP. [USGS's NAIP archive](https://www.usgs.gov/centers/eros/science/usgs-eros-archive-aerial-photography-national-agriculture-imagery-program-naip) documents public-domain imagery and download access. Service descriptions list multiple acquisition years and resolutions; this is not an independent per-route native-resolution/date audit. The narrow reviewed export path is now allowed in both pinned packs and the existing bounded temporary cache, with USDA/USFS/GeoPlatform credits. Other GeoPlatform services, credential URLs, lookalike hosts and arbitrary paths remain excluded. Commercial/private sources retain their existing independent policy.

## Revision and download recovery

The offline plan is now **`high-public-v2`** because its approved alias inventory changed. The portable TAR format remains version 1; current-plan fingerprint checks reject the earlier portable source contract. The two route inventories retain **5,337 / 8,177 sources**, full-model coverage and Z19. Request dimensions, projection, interpolation, PNG32 output and all DEM URLs/windows are unchanged. PC bodies are keyed by exact original URL, so existing validated USGS files can be reused unchanged under the new plan. Browser v1 staging stays retained; v2 currently starts a separate browser plan rather than copying that staged database content automatically.

The PC preparer now validates every available cached alias before attempting network acquisition. Previously a valid cached alternate could wait behind an unavailable preferred service on every resume. A service whose bounded transport retries are exhausted is moved behind other existing approved aliases for 120 seconds. Healthy source order returns after cooldown or successful validation; a cooled source is still tried if the others cannot provide valid coverage. Cached coverage failures and permanent request errors do not cool unrelated tile requests. No alternative is removed, no network concurrency is added, and each accepted source still passes the production validators. Disk-write errors stop preparation directly instead of triggering unnecessary downloads from other aliases.

Progress records distinguish retained/downloaded source counts, requested aliases and the first requested source index. The existing pause file and source/archive write checkpoints remain supported. The data queue is paused during isolated release measurements and resumes afterward; live progress is in `.review-cache/prepared-route-packs/output`, as described in [the acquisition guide](DEFAULT_PACK_ACQUISITION.md).

Loading and churn remain inconsistent; no native performance acceptance follows.

Extending the real-crop regression into image decoding/cropping found a source-reporting bug: pinned storage correctly retained the GeoPlatform origin, but the renderer labeled its image using the preferred lookup URL. The [pre-fix failure](naip-gap-recovery/provenance-before.json) occurs after the existing stored-provenance/hash assertions pass. The correction binds the actual supplying URL weakly to each verified Blob read, carries only fixed source labels into decoded/cropped images, and preserves alternative status through decoded-cache hits and Hybrid composition. Source bodies are not held by the weak metadata binding, private URLs do not enter rendered diagnostics, and existing pixels/requests/budgets are unchanged. Invalid stored source provenance now invalidates the affected asset instead of being reported as a supplying source.

The [post-fix real-image/storage regression](naip-gap-recovery/provenance-local-offline.json) passes with source networking disabled: decoded, cropped and cached imagery reports `geoplatform-naip` with `configuredAlternative: true`, while all original hashes and lookup aliases remain intact. Full `npm run verify` now passes **785 Windows tests with five skips**, both typechecks and production build.
